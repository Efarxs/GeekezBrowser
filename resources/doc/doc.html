Introduction

GeekEZ Browser is a specialized anti-detect browser built on Electron and the fingerprint-chromium engine, with sing-box integrated at the core. It is designed to solve multi-account association problems for cross-border e-commerce (TikTok, Amazon, Facebook, Shopee, etc.) by implementing deep system-level fingerprint spoofing.

Advanced Features

Hardware Randomization

  • Random CPU Cores (4/8/12/16)
  • Random Memory (4/8/16 GB)
  • This ensures every profile looks like a unique physical device.

WebRTC & IP Leak Protection

Forces disable_non_proxied_udp policy to physically block local IP leaks via WebRTC, ensuring only your proxy IP is visible.

sing-box Network Engine

Fully supports VLESS, VMess, Trojan, Shadowsocks (including SS-2022).

Chain Proxy Architecture

[Local] -> [Pre-Proxy] -> [Profile Proxy] -> [Target]

This architecture hides your real IP from the final proxy provider, adding an extra layer of anonymity.

Important Warning

If your local machine is already using a TUN proxy, do not enable pre-proxy, or the proxy chain may fail.

Usage Guide

1) Quick Start

  1. Open GeekEZ Browser and click New Profile.
  2. Paste a subscription URL or a single proxy link.
  3. Click Generate & Save to create the profile.

2) Advanced Features

  • Pre-Proxy: supports proxy nodes or subscription links. If the profile proxy can reach the target site directly, you can leave this disabled. Warning: If your local machine is already using a TUN proxy, do not enable pre-proxy, or the proxy chain may fail.
  • Extensions: add unpacked extension folders in Settings → Extension Management.
  • Remote Debugging: opens a debugging port for the profile so Puppeteer or DevTools can connect.
  • UA & WebGL Modify: useful for fingerprint testing and compatibility debugging, but not guaranteed to bypass risk-control detection.
  • Custom Launch Arguments: append Chrome launch flags to a single profile, such as window, performance, or experimental options.
  • API Server: after enabling it in Advanced Settings, you can automate profile management through the local REST API.

Proxy Link Formats

All protocols support standard proxy-link formats such as VMess, VLESS, Trojan, and Shadowsocks.

Below are common HTTP and SOCKS examples:

HTTP / HTTPS Proxies

# With username and password
http://user:pass@1.2.3.4:8080

# Without username and password
http://1.2.3.4:8080

# HTTPS form (handled as an HTTP proxy)
https://1.2.3.4:8080

SOCKS Proxies

# Standard format (with username and password)
socks://user:pass@1.2.3.4:1080

# Username only (no password)
socks5://user@1.2.3.4:1080

# No authentication
socks5://1.2.3.4:1080

# v2rayN style (base64(user:pass))
socks://dXNlcjpwYXNz@1.2.3.4:1080#remark

# Plain-text shorthand (treated as SOCKS by GeekEZ Browser)
1.2.3.4:1080
1.2.3.4:1080:user:pass

Direct Mode (No Proxy)

Direct

When the proxy link is set to Direct, GeekEZ Browser does not start the sing-box proxy engine for the profile and uses the local network directly.

FAQ

Q: Why is TikTok/Facebook still flagging my account?

A: Fingerprint isolation only protects device identity. You MUST use a high-quality Clean/Dedicated IP. Shared IPs are easily detected.

Q: White screen on startup?

A: Try setting Timezone to "Auto" in settings. Some sites (like Oracle) require precise time synchronization.

API 文档

GeekEZ Browser 提供一套本地 HTTP REST API，可通过脚本对指纹环境增删改查、启动、停止、备份。适用版本 v1.7.19。

  • 默认监听 http://127.0.0.1:12138，端口可在 设置 → API 服务 修改（改动后自动重启）。
  • 只监听 127.0.0.1，无认证，请勿转发到公网。
  • 请求/响应均为 application/json（/api/open 流式模式除外）。
  • 如需 CDP 接管浏览器，请同时打开 设置 → 远程调试，之后创建的 profile 才会分配调试端口。
  • 路径参数 :idOrName 可为 profile 的 UUID 或名称（名称需 URL 编码），ID 优先。

接口一览

  • GET /api/status — 查询正在运行的环境列表
  • GET /api/profiles — 查询所有 profile（支持 ?tag=）
  • GET /api/profiles/:idOrName — 查询单个 profile 详情
  • GET /api/profiles/:idOrName/runtime — 查询单个 profile 运行状态
  • POST /api/profiles — 创建 profile
  • PUT /api/profiles/:idOrName — 修改 profile
  • POST /api/profiles/:idOrName/duplicate — 复制 profile
  • DELETE /api/profiles/:idOrName — 删除 profile
  • GET /api/open/:idOrName — 启动（支持 ?clean=true、?verify=browser）
  • POST /api/profiles/:idOrName/stop — 停止（支持 ?keepProxy=true）
  • GET /api/export/all — 导出加密全量备份
  • GET /api/export/fingerprint — 导出 YAML 指纹清单
  • POST /api/import — 导入 YAML 或加密备份
  • GET / PATCH /api/settings — 读取 / 部分更新设置
  • GET /api/kernels、POST/DELETE /api/kernels/:version — 内核管理
  • POST /api/proxy/latency — 测试代理连通性与延迟

通用说明

  • :idOrName 均支持环境 ID（UUID）或名称。
  • 列表接口支持按标签精确筛选：GET /api/profiles?tag=标签名。
  • 若开启"远程调试"，创建/更新返回中会包含 remoteDebugPort。
  • POST/PUT 支持 args 字段，写入后永久保存为启动参数；GET /api/open?args= 仅本次生效。
  • notes 为环境备注；列表接口不返回备注，详情/创建/更新返回完整环境对象。
  • 时间戳统一为 UTC 毫秒；"remote port" 字段名含空格，JS 读取用 obj['remote port']。

创建 / 修改环境字段

POST /api/profiles 与 PUT /api/profiles/:idOrName body 结构一致，字段均可选，未传保留原值（创建时用默认/随机）。必须的只有实际业务需要的 name。

顶层字段：

  • name — 环境名，重名自动追加 -02/-03。
  • proxyStr — 代理串，支持 socks5://、http://、vmess://、vless://、trojan://、ss://、ssh://、hy2://、tuic://。留空 = 直连。
  • tags — 标签，数组或逗号分隔字符串。
  • notes — 备注（账号/密码/操作方法等）。
  • preProxyOverride — 前置代理开关：default（跟随全局）/ on（强制启用）/ off（强制禁用，绝对总关，屏蔽 preProxyStr）。
  • preProxyStr — 本 profile 专属前置代理 URL（如 socks5://127.0.0.1:7890）。填了就在主代理之前先经过它，覆盖全局前置代理池与 mode，且无需打开全局开关即生效（非空即隐含 on）；留空跟随全局；preProxyOverride:'off' 时忽略本字段。v1.7.18 新增。
  • args / customArgs — 附加 Chromium 命令行参数（多行或空格分隔的 --xxx）。
  • ignoreCertErrors — 忽略证书错误，默认 false。
  • resetOnLaunch — 每次启动重置指纹与 user-data，默认 false。
  • headless — v1.7.17 新增。无头模式，追加 --headless=new 并屏蔽 navigator.webdriver；仅适合自动化/服务端，主号勿开。默认 false。
  • debugPort — 固定调试端口，留空按需自动分配（从 24000 顺序填空洞，范围 24000-65000）。需先开启远程调试。
  • kernelVersion — 该 profile 使用的 fingerprint-chromium 版本（如 148.0.7778.215），留空/null 跟随内置 pinned 版本，首次启动如未安装会触发下载。
  • fingerprint — 指纹对象（见下）。

fingerprint 字段（均可选）：v1.7 起指纹由内核从 --fingerprint=<seed> 派生（seed 绑定 profile ID），Canvas/Audio/WebGL/TLS 自动生成，无需在 API 传。真正影响运行时的字段：

  • uaMode — spoof（伪装 UA/品牌）/ none（不改 UA 只隔离），默认 none。
  • platform — Win32 / MacIntel / Linux x86_64，需显式指定。
  • browserType — chrome / edge，默认 chrome（同时决定 uTLS 指纹）。
  • browserMajorVersion — 主版本，目前只支持 148（其他值会被规范化回 148）。
  • browserFullVersion — 完整 patch 号（如 148.0.7778.167），不传从真实 Chrome 148 stable 池随机抽。
  • userAgent — 覆盖 UA，启动时自动做 Chrome UA-Reduction（Chrome/X.0.0.0 + Full-Version-List）。
  • screen — { "width": 1920, "height": 1080 }，用作启动窗口大小。
  • language — 主语言如 en-US；auto 或不传 = 按出口 IP 匹配。v1.7.17 修复：auto 现在真正把派生语言推给 Chrome（此前会泄漏宿主 locale）。依赖旧行为请显式传目标语言。
  • languages — 语言列表如 ["en-US","en"]，未传从 language 派生。
  • timezone — IANA 时区如 America/New_York；Auto/不传 = 跟随 IP。
  • hardwareConcurrency — CPU 核数 4/8/12/16。
  • deviceMemory — 内存 GB 8/16/32（现代 Chrome 报告真实物理内存，非旧规范上限 8）。
  • geolocation — { "latitude":40.7, "longitude":-74.0, "accuracy":100 }，劫持 navigator.geolocation。
  • city — 仅 UI 元数据，实际生效的是 geolocation。
  • disabledSpoofing — 关闭内核对指定维度的伪装，取值 canvas/audio/clientrects/gpu 的子集，默认 []。需 kernel 144+。

已废弃/忽略字段：canvasNoise、audioNoise、noiseSeed、webgl/webglProfile、tlsClientHello、userAgentMetadata（均由内核 seed / browserType 自动派生）。

前置代理三者关系（重要）

一个环境到底走不走前置、走哪个，由三者按优先级瀑布决定 —— 从上往下，命中即停：

  1. ① preProxyOverride = off？ → 绝对不走前置，忽略其余一切。
  2. ② 本环境填了 preProxyStr？ → 走这个专属前置，忽略全局池 / mode / 全局总开关（非空即自带"开"）。
  3. ③ 用不用全局池？ 由 preProxyOverride 决定：on = 用（即使左上角总开关关着）；default = 跟随全局总开关 settings.enablePreProxy。用池时具体选哪个节点看全局 mode（single / balance / failover）。

换句话说：preProxyOverride 管"用不用 / 强制开关"，preProxyStr 管"用我自己的这一个（覆盖全局）"，settings.enablePreProxy 只是全局池的总开关（仅在 default 且没填专属时才起作用）。真值表：

  • override=off + 任意 → 不走前置（绝对关）
  • override=default/on + preProxyStr 有值 → 走专属前置（忽略池/mode/总开关）
  • override=on + preProxyStr 空 → 走全局池（按 mode 选节点，无视总开关）
  • override=default + preProxyStr 空 + 总开关=开 → 走全局池
  • override=default + preProxyStr 空 + 总开关=关 → 不走前置

接口与示例

1) 查询运行状态 GET /api/status

curl http://127.0.0.1:12138/api/status

返回 { success, running[], count }；?keepProxy=true 停止后保留隧道的 profile 会出现在 detachedTunnels[]。

2) 查询环境列表 GET /api/profiles（?tag= 按标签过滤）

curl "http://127.0.0.1:12138/api/profiles?tag=tiktok"

3) 查询单个环境详情 GET /api/profiles/:idOrName

curl http://127.0.0.1:12138/api/profiles/TikTok-US-01

4) 创建环境 POST /api/profiles

curl -X POST http://127.0.0.1:12138/api/profiles \
  -H "Content-Type: application/json" \
  -d '{
    "name": "TikTok-US-01",
    "proxyStr": "socks5://user:pass@1.2.3.4:1080",
    "tags": ["tiktok", "us"],
    "preProxyStr": "socks5://127.0.0.1:7890",
    "fingerprint": {
      "uaMode": "spoof",
      "platform": "Win32",
      "browserMajorVersion": 148,
      "language": "en-US",
      "timezone": "America/Los_Angeles",
      "disabledSpoofing": ["canvas", "audio"]
    }
  }'

无头自动化示例（追加 "headless": true）：启动后无窗口，仍可通过 /api/open 返回的 "remote port" 接 Playwright/DevTools。

5) 修改环境 PUT /api/profiles/:idOrName（运行中返回 409，需先停止）

curl -X PUT "http://127.0.0.1:12138/api/profiles/TikTok-US-01" \
  -H "Content-Type: application/json" \
  -d '{ "proxyStr": "socks5://new:pass@5.6.7.8:1080", "tags": ["tiktok","us","backup"] }'

6) 复制环境 POST /api/profiles/:idOrName/duplicate

curl -X POST "http://127.0.0.1:12138/api/profiles/TikTok-US-01/duplicate" \
  -H "Content-Type: application/json" \
  -d '{ "name": "TikTok-US-01-backup" }'

fingerprint / customArgs / kernelVersion / preProxyOverride / preProxyStr / resetOnLaunch / headless 都会带过来；新 profile 获得新 UUID（→ 新 seed → 不同 canvas/audio/WebGL 哈希）与新 debugPort。

7) 删除环境 DELETE /api/profiles/:idOrName（运行中返回 409）

curl -X DELETE "http://127.0.0.1:12138/api/profiles/TikTok-US-01"

8) 启动环境 GET /api/open/:idOrName

# JSON 模式
curl "http://127.0.0.1:12138/api/open/TikTok-US-01?stream=false"
# 干净启动（临时 user-data，不加载扩展/会话；注意会抑制调试端口）
curl "http://127.0.0.1:12138/api/open/TikTok-US-01?clean=true"
# 浏览器级验证（起来后 CDP 主动导航探测，通了才算成功；需开远程调试，+2~10s）
curl "http://127.0.0.1:12138/api/open/TikTok-US-01?verify=browser"
# 本次临时追加启动参数（可重复传）
curl "http://127.0.0.1:12138/api/open/TikTok-US-01?args=--disable-gpu&args=--window-size=1280,720"

响应里的 "remote port"（含空格）是本次实际绑定的调试端口，可能因端口冲突被动态降级 —— CDP 一律按此值连，别硬编码 debugPort。

8.1) 启动查询参数：stream（true/false，curl 默认流式）、lang（en/cn 提示语言）、clean、verify=browser + verifyUrl + verifyStrict（默认拒 3xx，防热点门户假阳性）、args。验证失败会自动 stop profile 并返回 500。

9) 停止环境 POST /api/profiles/:idOrName/stop（?keepProxy=true 只关浏览器、保留 sing-box 隧道）

curl -X POST "http://127.0.0.1:12138/api/profiles/TikTok-US-01/stop"

10) 查询单个运行状态 GET /api/profiles/:idOrName/runtime

curl http://127.0.0.1:12138/api/profiles/TikTok-US-01/runtime

返回 running/launching/"remote port"（本次实际）/persistedDebugPort/kernelVersion。

11) 导出加密全量备份 GET /api/export/all?password=你的密码（含指纹+浏览器数据+Cookie+密码）

curl "http://127.0.0.1:12138/api/export/all?password=my-secret" -o backup.json

部分 profile 读取失败时响应附带 warnings，success 仍为 true。

12) 导出 YAML 指纹清单 GET /api/export/fingerprint（不含浏览器数据/Cookie/密码）

curl "http://127.0.0.1:12138/api/export/fingerprint"

13) 导入 POST /api/import（YAML 或加密备份 Base64；重名自动追加后缀）

curl -X POST http://127.0.0.1:12138/api/import \
  -H "Content-Type: application/json" \
  -d '{ "content": "YAML 文本或加密备份的 Base64", "password": "加密备份必填，YAML 可不填" }'

14) 应用设置 GET / PATCH /api/settings

curl -X PATCH http://127.0.0.1:12138/api/settings \
  -H "Content-Type: application/json" \
  -d '{ "enableRemoteDebugging": true }'

PATCH 只接受白名单标量字段（enableRemoteDebugging、enablePreProxy、mode、selectedId、apiPort、lang、closeBehavior 等），均有类型/取值校验；数组字段（preProxies/subscriptions/userExtensions）拒绝（400）。改 enableApiServer/apiPort 返回 restartRequired:true。

15) 内核管理 /api/kernels

# 列出已装（?available=true 同时拉上游，?measureSize=true 计算体积）
curl "http://127.0.0.1:12138/api/kernels?available=true"
# 安装（同步阻塞直到下载解压完成）
curl -X POST http://127.0.0.1:12138/api/kernels/144.0.7559.132
# 卸载（拒绝卸载 pinned 版本或运行中版本，409）
curl -X DELETE http://127.0.0.1:12138/api/kernels/144.0.7559.132

16) 代理测试 POST /api/proxy/latency

# 直接测 URL（单跳，不套前置）
curl -X POST http://127.0.0.1:12138/api/proxy/latency \
  -H "Content-Type: application/json" \
  -d '{ "proxyStr": "socks5://user:pass@1.2.3.4:1080" }'
# 按 profile 走完整链路（推荐；有 preProxyStr 优先走专属前置）
curl -X POST http://127.0.0.1:12138/api/proxy/latency \
  -H "Content-Type: application/json" \
  -d '{ "profileId": "TikTok-US-01" }'

返回 { success, latency, target, chain }；chain.preProxy 为所用前置（内联前置显示 profile，null 表示单跳）。加 "chain": false 可强制单跳诊断。很多境外代理需走前置才通，建议用 profileId 模式预筛。

错误码

  • 200 成功 · 400 参数错误 · 404 不存在 · 409 运行中不允许改/删 · 500 内部错误
  • 错误统一返回 { "success": false, "error": "描述" }。

结合 CDP 自动化

前置条件：① 设置 → 远程调试 已开；② profile 已分配 debugPort；③ 未用 clean=true（该模式剥离调试端口）。启动后 "remote port" 即标准 CDP 端口，可直接对接 Playwright / Puppeteer：

const res = await fetch('http://127.0.0.1:12138/api/open/TikTok-US-01?stream=false').then(r => r.json());
const port = res['remote port'];   // 注意字段名带空格
const browser = await chromium.connectOverCDP('http://127.0.0.1:' + port);

完整 REST 契约与更多示例见项目内 docs/api/API.md（本页与其保持同步）。

API Documentation

GeekEZ Browser exposes a local HTTP REST API to create, query, launch, stop and back up fingerprint profiles from scripts. Applies to v1.7.19.

  • Listens on http://127.0.0.1:12138 by default; the port is configurable under Settings → API Server (auto-restarts on change).
  • Binds to 127.0.0.1 only, no authentication — never forward it to the public internet.
  • Requests/responses are application/json (except the streaming mode of /api/open).
  • To drive the browser over CDP, also enable Settings → Remote Debugging; only profiles created afterwards get a debug port.
  • The path parameter :idOrName accepts a profile UUID or name (URL-encode names); ID wins.

Endpoint overview

  • GET /api/status — list running profiles
  • GET /api/profiles — list all profiles (supports ?tag=)
  • GET /api/profiles/:idOrName — profile detail
  • GET /api/profiles/:idOrName/runtime — runtime state of one profile
  • POST /api/profiles — create a profile
  • PUT /api/profiles/:idOrName — update a profile
  • POST /api/profiles/:idOrName/duplicate — clone a profile
  • DELETE /api/profiles/:idOrName — delete a profile
  • GET /api/open/:idOrName — launch (supports ?clean=true, ?verify=browser)
  • POST /api/profiles/:idOrName/stop — stop (supports ?keepProxy=true)
  • GET /api/export/all — encrypted full backup
  • GET /api/export/fingerprint — YAML fingerprint export
  • POST /api/import — import YAML or encrypted backup
  • GET / PATCH /api/settings — read / partially update settings
  • GET /api/kernels, POST/DELETE /api/kernels/:version — kernel management
  • POST /api/proxy/latency — proxy connectivity & latency test

General notes

  • :idOrName accepts a profile ID (UUID) or name.
  • List endpoint filters by tag: GET /api/profiles?tag=name.
  • When Remote Debugging is on, create/update responses include remoteDebugPort.
  • POST/PUT accept an args field saved as persistent launch args; GET /api/open?args= applies to that launch only.
  • notes holds profile notes; list responses omit notes, detail/create/update return the full object.
  • Timestamps are UTC ms; the field "remote port" contains a space — read it as obj['remote port'].

Create / Update fields

POST /api/profiles and PUT /api/profiles/:idOrName share the same body; every field is optional and omitted fields keep their previous value (random/default on create).

Top-level fields:

  • name — profile name; duplicates auto-suffix -02/-03.
  • proxyStr — proxy string: socks5://, http://, vmess://, vless://, trojan://, ss://, ssh://, hy2://, tuic://. Empty = direct.
  • tags — array or comma-separated string.
  • notes — free-form notes (account/password/workflow).
  • preProxyOverride — pre-proxy switch: default (follow global) / on (force) / off (hard kill-switch, masks preProxyStr).
  • preProxyStr — this profile's own pre-proxy URL (e.g. socks5://127.0.0.1:7890). Chains through it before the main proxy, overriding the global pre-proxy pool and mode, and works without the global toggle (non-empty implies on). Empty = follow global; ignored when preProxyOverride:'off'. Added in v1.7.18.
  • args / customArgs — extra Chromium flags (newline/space separated --xxx).
  • ignoreCertErrors — ignore cert errors, default false.
  • resetOnLaunch — wipe fingerprint & user-data each launch, default false.
  • headless — added in v1.7.17. Headless mode: adds --headless=new and masks navigator.webdriver. For automation/server use only; do not use for primary accounts. Default false.
  • debugPort — fixed debug port; empty = auto-assign (fills gaps from 24000, range 24000-65000). Requires Remote Debugging.
  • kernelVersion — fingerprint-chromium version for this profile (e.g. 148.0.7778.215); empty/null follows the built-in pinned version and downloads on first launch if missing.
  • fingerprint — fingerprint object (below).

fingerprint fields (all optional): since v1.7 the fingerprint is derived by the kernel from --fingerprint=<seed> (seed bound to profile ID); Canvas/Audio/WebGL/TLS are generated automatically. Runtime-relevant fields:

  • uaMode — spoof / none, default none.
  • platform — Win32 / MacIntel / Linux x86_64, must be explicit.
  • browserType — chrome / edge, default chrome (also sets uTLS).
  • browserMajorVersion — currently only 148 (other values normalize to 148).
  • browserFullVersion — full patch (e.g. 148.0.7778.167); random from the real Chrome 148 stable pool if omitted.
  • userAgent — override UA; the app applies Chrome UA-Reduction on launch (Chrome/X.0.0.0 + Full-Version-List).
  • screen — { "width": 1920, "height": 1080 }, used as the launch window size.
  • language — e.g. en-US; auto/omitted matches the exit IP. Fixed in v1.7.17: auto now actually pushes the derived language to Chrome (previously leaked the host locale).
  • languages — e.g. ["en-US","en"]; derived from language if omitted.
  • timezone — IANA tz e.g. America/New_York; Auto/omitted follows the IP.
  • hardwareConcurrency — CPU cores 4/8/12/16.
  • deviceMemory — RAM GB 8/16/32 (modern Chrome reports real physical RAM, not the old spec cap of 8).
  • geolocation — { "latitude":40.7, "longitude":-74.0, "accuracy":100 }, hooks navigator.geolocation.
  • city — UI metadata only; geolocation is what takes effect.
  • disabledSpoofing — disable kernel spoofing for given dimensions, subset of canvas/audio/clientrects/gpu, default []. Requires kernel 144+.

Deprecated/ignored fields: canvasNoise, audioNoise, noiseSeed, webgl/webglProfile, tlsClientHello, userAgentMetadata (all derived by the kernel seed / browserType).

How the three pre-proxy settings interact (important)

Whether a profile uses a pre-proxy — and which one — is decided by a priority waterfall. Top to bottom, first match wins:

  1. ① preProxyOverride = off? → never use a pre-proxy; everything else is ignored.
  2. ② Does the profile set preProxyStr? → use that dedicated pre-proxy, ignoring the global pool / mode / global toggle (non-empty implies "on").
  3. ③ Use the global pool? Decided by preProxyOverride: on = yes (even if the top-left global toggle is off); default = follow the global toggle settings.enablePreProxy. Which pool node is picked follows the global mode (single / balance / failover).

In short: preProxyOverride controls "use it / force on-off", preProxyStr means "use this specific one (override the global pool)", and settings.enablePreProxy is just the master switch for the shared pool (relevant only when default and no dedicated URL is set). Truth table:

  • override=off + anything → no pre-proxy (hard off)
  • override=default/on + preProxyStr set → use the dedicated pre-proxy (ignores pool/mode/toggle)
  • override=on + preProxyStr empty → use the global pool (per mode, ignores the toggle)
  • override=default + preProxyStr empty + toggle on → use the global pool
  • override=default + preProxyStr empty + toggle off → no pre-proxy

Endpoints & examples

1) Status GET /api/status

curl http://127.0.0.1:12138/api/status

Returns { success, running[], count }; profiles stopped with ?keepProxy=true appear in detachedTunnels[].

2) List profiles GET /api/profiles (?tag= to filter)

curl "http://127.0.0.1:12138/api/profiles?tag=tiktok"

3) Profile detail GET /api/profiles/:idOrName

curl http://127.0.0.1:12138/api/profiles/TikTok-US-01

4) Create POST /api/profiles

curl -X POST http://127.0.0.1:12138/api/profiles \
  -H "Content-Type: application/json" \
  -d '{
    "name": "TikTok-US-01",
    "proxyStr": "socks5://user:pass@1.2.3.4:1080",
    "tags": ["tiktok", "us"],
    "preProxyStr": "socks5://127.0.0.1:7890",
    "fingerprint": {
      "uaMode": "spoof",
      "platform": "Win32",
      "browserMajorVersion": 148,
      "language": "en-US",
      "timezone": "America/Los_Angeles",
      "disabledSpoofing": ["canvas", "audio"]
    }
  }'

For headless automation add "headless": true: launches with no window; connect Playwright/DevTools via the "remote port" from /api/open.

5) Update PUT /api/profiles/:idOrName (409 while running — stop first)

curl -X PUT "http://127.0.0.1:12138/api/profiles/TikTok-US-01" \
  -H "Content-Type: application/json" \
  -d '{ "proxyStr": "socks5://new:pass@5.6.7.8:1080", "tags": ["tiktok","us","backup"] }'

6) Duplicate POST /api/profiles/:idOrName/duplicate

curl -X POST "http://127.0.0.1:12138/api/profiles/TikTok-US-01/duplicate" \
  -H "Content-Type: application/json" \
  -d '{ "name": "TikTok-US-01-backup" }'

Carries fingerprint / customArgs / kernelVersion / preProxyOverride / preProxyStr / resetOnLaunch / headless; the copy gets a new UUID (→ new seed → different canvas/audio/WebGL hashes) and a fresh debugPort.

7) Delete DELETE /api/profiles/:idOrName (409 while running)

curl -X DELETE "http://127.0.0.1:12138/api/profiles/TikTok-US-01"

8) Launch GET /api/open/:idOrName

# JSON mode
curl "http://127.0.0.1:12138/api/open/TikTok-US-01?stream=false"
# Clean launch (temp user-data, no extensions/session; suppresses the debug port)
curl "http://127.0.0.1:12138/api/open/TikTok-US-01?clean=true"
# Browser-level verify (CDP navigation probe after launch; needs Remote Debugging, +2-10s)
curl "http://127.0.0.1:12138/api/open/TikTok-US-01?verify=browser"
# One-time extra launch args (repeatable)
curl "http://127.0.0.1:12138/api/open/TikTok-US-01?args=--disable-gpu&args=--window-size=1280,720"

The response "remote port" (with a space) is the port actually bound this launch — it may be dynamically downgraded on conflict. Always connect CDP to this value, never hard-code debugPort.

8.1) Launch query params: stream (true/false, curl streams by default), lang (en/cn), clean, verify=browser + verifyUrl + verifyStrict (rejects 3xx by default to avoid captive-portal false positives), args. A failed verify auto-stops the profile and returns 500.

9) Stop POST /api/profiles/:idOrName/stop (?keepProxy=true keeps the sing-box tunnel)

curl -X POST "http://127.0.0.1:12138/api/profiles/TikTok-US-01/stop"

10) Runtime state GET /api/profiles/:idOrName/runtime

curl http://127.0.0.1:12138/api/profiles/TikTok-US-01/runtime

Returns running/launching/"remote port" (this launch)/persistedDebugPort/kernelVersion.

11) Encrypted full backup GET /api/export/all?password=your-pw (fingerprint + browser data + cookies + passwords)

curl "http://127.0.0.1:12138/api/export/all?password=my-secret" -o backup.json

If some profiles fail to read, the response adds warnings while success stays true.

12) YAML fingerprint export GET /api/export/fingerprint (no browser data/cookies/passwords)

curl "http://127.0.0.1:12138/api/export/fingerprint"

13) Import POST /api/import (YAML or Base64 encrypted backup; duplicates auto-suffix)

curl -X POST http://127.0.0.1:12138/api/import \
  -H "Content-Type: application/json" \
  -d '{ "content": "YAML text or Base64 of an encrypted backup", "password": "required for encrypted, optional for YAML" }'

14) Settings GET / PATCH /api/settings

curl -X PATCH http://127.0.0.1:12138/api/settings \
  -H "Content-Type: application/json" \
  -d '{ "enableRemoteDebugging": true }'

PATCH accepts only whitelisted scalar fields (enableRemoteDebugging, enablePreProxy, mode, selectedId, apiPort, lang, closeBehavior, ...), all type/range validated; array fields (preProxies/subscriptions/userExtensions) are rejected (400). Changing enableApiServer/apiPort returns restartRequired:true.

15) Kernel management /api/kernels

# List installed (?available=true also pulls upstream, ?measureSize=true computes size)
curl "http://127.0.0.1:12138/api/kernels?available=true"
# Install (blocks until download+extract finishes)
curl -X POST http://127.0.0.1:12138/api/kernels/144.0.7559.132
# Uninstall (refuses the pinned version or one in use, 409)
curl -X DELETE http://127.0.0.1:12138/api/kernels/144.0.7559.132

16) Proxy test POST /api/proxy/latency

# Test a URL directly (single hop, no pre-proxy)
curl -X POST http://127.0.0.1:12138/api/proxy/latency \
  -H "Content-Type: application/json" \
  -d '{ "proxyStr": "socks5://user:pass@1.2.3.4:1080" }'
# Test a profile's full chain (recommended; an inline preProxyStr wins)
curl -X POST http://127.0.0.1:12138/api/proxy/latency \
  -H "Content-Type: application/json" \
  -d '{ "profileId": "TikTok-US-01" }'

Returns { success, latency, target, chain }; chain.preProxy is the pre-proxy used (an inline one shows profile, null = single hop). Add "chain": false to force a single-hop diagnostic. Many overseas proxies only work through a pre-proxy, so prefer the profileId mode for pre-flight checks.

Error codes

  • 200 ok · 400 bad request · 404 not found · 409 running (edit/delete refused) · 500 internal error
  • Errors return { "success": false, "error": "message" }.

Automating with CDP

Prerequisites: (1) Remote Debugging enabled; (2) the profile has a debugPort; (3) not launched with clean=true (that mode strips the debug port). After launch, "remote port" is a standard CDP endpoint for Playwright / Puppeteer:

const res = await fetch('http://127.0.0.1:12138/api/open/TikTok-US-01?stream=false').then(r => r.json());
const port = res['remote port'];   // note the space in the field name
const browser = await chromium.connectOverCDP('http://127.0.0.1:' + port);

The full REST contract and more examples live in docs/api/API.md (this page is kept in sync with it).
